# Changelog

Notable changes per release, newest first. Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

ehrtslib versions three artefacts independently. Headings are library versions (tags `vX.Y`, with patch `0` omitted) unless marked **demo** or **TAAAT**.

Add an entry under **Unreleased** in every PR that changes user-visible behaviour. The release PR renames that section to the new version. History before 0.1.0 is in git, not here.

## [0.12.0] - 2026-11-05

- **Contribution Builder.** When a CDR replaces the client-sent versioned-object uuid, `record-commit` stores both the provisional uuid and the stored uuid. The `serverAssignedUids` warning stays. Inner node uids keep the provisional prefix ([#176](https://github.com/ErikSundvall/ehrtslib/issues/176)).
- **Contribution Builder.** `continueCommitted` starts a modify draft from a committed draft, with the stored version uid as its base. The committed draft stays closed, and operations after `record-commit` in a merged log are skipped as `already-committed`. The next commit sends `preceding_version_uid` and change type modification, or amendment when asked. A failed commit of that draft uses the conflict flow, including status 412. On a shared build only a `committer` commits, the composer stays explicit, members who changed content are recorded in `other_participations`, and text edits compact to one `set-value` per author and field before the audit hash ([#177](https://github.com/ErikSundvall/ehrtslib/issues/177)).
- `webTemplateToOpt` keeps node ids that are slugged from archetype terms. A nested at-code is stored on the archetype in its path (`nested.en.v1` ordinal no longer comes back as `count`). A renamed sibling does not replace the shared at-code, so RIPPLE `request` / `request_3` and `method` / `method_1` stay put, and a node whose only name is a fallback (`cluster`, `element`) keeps that text. ACTION `ism_transition` and `current_state` keep existence 1..1 ([#271](https://github.com/ErikSundvall/ehrtslib/issues/271)).

## [0.11.0] - 2026-11-02

- An ELEMENT with no value constraint lists the 16 `<type>_value` children EHRbase and FerroEHR both list (no `state_value`, no `scale_value`). `interval_of_<t>_value` is still read though it is not listed. `webTemplateToOpt` turns that list back into an ELEMENT with no value constraint ([#267](https://github.com/ErikSundvall/ehrtslib/issues/267)).
- **Contribution Builder.** The remaining draft operations are in the log: `move-instance`, `assign-uid`, `set-participation`, `set-lifecycle`, `migrate-template`, `import` (canonical, FLAT or STRUCTURED), `discard`, `edit-text`, and build membership (`join-build`, `leave-build`, `set-role`). A `committer` may edit; a `viewer` may not. Before the commit hash, text edits compact to one `set-value` per author and field, and each author who changed an entry is recorded in `other_participations` with function `data entry` ([#171](https://github.com/ErikSundvall/ehrtslib/issues/171)).
- **Contribution Builder.** `rev` on `set-value` and `edit-text` is optional. Omitted, the write applies (single caller). Present, a field changed since that `rev` is refused with `changed-by-someone-else` and the current value. A multi-caller build can require `rev` ([#243](https://github.com/ErikSundvall/ehrtslib/issues/243)).
- **Contribution Builder.** After each operation a quick check marks changed nodes `invalid` when a present value breaks a constraint, and does not reject the edit. `validationState` reports `unfinished` and `invalid`, whether the build can commit as complete or incomplete, and per-CDR advice: EHRbase 2.36 rejects an incomplete version that still misses mandatory template content, FerroEHR 5.4.1 accepts it. The status is derived, not written to the log ([#173](https://github.com/ErikSundvall/ehrtslib/issues/173)).
- **Contribution Builder.** `rebase` replays a modify draft onto the latest version. Each conflict is a `resolve` operation (`keep-ours`, `keep-theirs`, `custom`, `drop`). The new draft's base is that latest version, so the next commit sends it as `preceding_version_uid`. Further edits of a committed draft are a new update-version ([#177](https://github.com/ErikSundvall/ehrtslib/issues/177)).
- **Contribution Builder.** When a CDR assigns its own versioned-object uuid, `record-commit` stores `storedObjectUuid`. Inner node uids keep the provisional prefix. The sent composition is not rewritten ([#176](https://github.com/ErikSundvall/ehrtslib/issues/176)).
- **Contribution Builder.** Optional Automerge 3 multi-caller adapter at `addons/cb_automerge/mod.ts` (`ehrtslib/contribution-builder-automerge`). It syncs the same operation log, requires `rev`, replays with the concurrent apply policy (skip and report, append when an anchor is gone), and can merge free text with an Automerge text object (profile `automerge-3`). Not part of `mod.ts` or `contribution_builder/mod.ts` ([#170](https://github.com/ErikSundvall/ehrtslib/issues/170)).
- FLAT and STRUCTURED read back every key their writers emit. A DV_CODED_TEXT on a DV_TEXT node keeps `|code`, `|value`, `|terminology` and reads as DV_CODED_TEXT; all three are required (the node has nothing to complete them from, so the terminology is not defaulted), and `local` needs a code of the archetype, else a `coded-text-mismatch` issue. The value of an ELEMENT without a value constraint is written and read under a `<type>_value` segment (`…/any/text_value`, `…/any/quantity_value|magnitude`), as in Simplified Formats §5.8; it was a bare key without its type that the reader rejected. A DV_INTERVAL<T> is `interval_of_<t>_value` (`…/any/interval_of_quantity_value/lower|magnitude`), as Better and FerroEHR name it ([#255](https://github.com/ErikSundvall/ehrtslib/issues/255)).
- `webTemplateToOpt` keeps name-constrained siblings (two `SECTION.adhoc` headings, `[id and name/value='X']` or `[id,'X']`) as separate objects with a `name` constraint, so OPT → Web Template → OPT → Web Template keeps both with their names and children. L10n path annotations written from a Web Template keep the name predicate ([#256](https://github.com/ErikSundvall/ehrtslib/issues/256)).
- **Behaviour change.** Flattening keeps primitive constraints. A `C_TERMINOLOGY_CODE` used to be cloned into a bare `C_PRIMITIVE_OBJECT`, and `C_PRIMITIVE_OBJECT.item` was dropped, so coded text in a flattened template lost its terminology and code list. Generated data then had a string `defining_code`, written to FLAT as `_defining_code`. OPT 1.4 XML reads a CODE_PHRASE constraint as `C_TERMINOLOGY_CODE` whatever its xsi type: ehrtslib up to 0.10 wrote such constraints as `C_DV_TEXT`, which is not an OPT 1.4 type, and now writes `C_CODE_PHRASE`. Template content and binding hashes of affected templates change ([#258](https://github.com/ErikSundvall/ehrtslib/issues/258)).
- `validateFlatPayload` accepts the bounds of a DV_INTERVAL<T> node (`…/interval_quantity/lower|magnitude`, `…/interval_count/upper`) and checks their suffixes against T. They were reported as unknown keys, although the reader reads them ([#259](https://github.com/ErikSundvall/ehrtslib/issues/259)).
- **Behaviour change.** An ELEMENT whose value may have one of several types (DV_QUANTITY or DV_COUNT, say) gets one Web Template child per type: `<type>_value` at `<element>/value`, min 0, as EHRbase and Better build it. FLAT and STRUCTURED write and read the value under that child (`…/choice/quantity_value|magnitude`). Before, the Web Template had only the first type, and the writer wrote `…/choice|magnitude`. The DV_CODED_TEXT/DV_TEXT pair stays one node ([#260](https://github.com/ErikSundvall/ehrtslib/issues/260)).
- A template that uses one archetype more than once with different OPT terms (two `SECTION.adhoc` roots, "Vital signs" and "Calculated scales") keeps each occurrence's terms. Later occurrences get an occurrence scope `<archetype id>#<n>` (`term_occurrence_scope`, table in `occurrence_term_definitions`); look them up with `termScopeOf` and `termTablesByScope`, or `archetypeTermBagsForLanguage`. The last occurrence's terms used to win for all ([#261](https://github.com/ErikSundvall/ehrtslib/issues/261)).
- `webTemplateToOpt` keeps the names of each occurrence of a reused archetype (ips.v0: ACTION.medication as "Medication statement" and "Immunization statement"). A later occurrence with other names gets its own term scope, as in #261, so OPT → Web Template → OPT → Web Template keeps every node id and name; ips used to lose 88 of 520 nodes ([#262](https://github.com/ErikSundvall/ehrtslib/issues/262)).
- **Behaviour change.** The FLAT reader rejects two `<type>_value` keys on one ELEMENT instance (`…/labresult/text_value` and `…/labresult/quantity_value|magnitude`) with an `element-value` error issue; `deserializeFromFlat` throws `FlatElementValueError`. It used to keep one value and drop the other silently, as EHRbase and FerroEHR still do ([#263](https://github.com/ErikSundvall/ehrtslib/issues/263)).
- **Behaviour change.** `…/<element>/_value` on a choice or unconstrained ELEMENT is an `element-value` error; use `<type>_value`. It used to be read as a DV_TEXT ([#264](https://github.com/ErikSundvall/ehrtslib/issues/264)).
- **Behaviour change.** The FLAT reader no longer builds invalid RM. A value plus `_null_flavour`/`_null_reason` on one ELEMENT is an `element-value` error (it used to build both on an unconstrained ELEMENT and drop the null flavour on a choice ELEMENT); `_null_flavour` alone on a choice ELEMENT is now read. Plain text as the bare value of a coded node is a `coded-text-mismatch` error pointing to `|other` (it used to build a DV_CODED_TEXT without `defining_code`) ([#265](https://github.com/ErikSundvall/ehrtslib/issues/265)).
- **Behaviour change.** `validateFlatPayload` also reports what the FLAT reader rejects (`coded-text-mismatch`, `element-value`, `unknown-key`), so it is no longer `valid` for a payload `deserializeFromFlat` throws on. `strictUnknownKeys` now defaults to `true`, as the reader's `unknownKeys` defaults to `"error"`; pass `false` for warnings ([#266](https://github.com/ErikSundvall/ehrtslib/issues/266)).
- **Behaviour change.** A collapsed ELEMENT leaf in the Web Template has the ELEMENT's `min`/`max`, not its value's, as EHRbase and Better give. An optional ELEMENT (blood pressure systolic, 0..1) used to show `min: 1`, and `validateFlatPayload` warned that it was missing ([#268](https://github.com/ErikSundvall/ehrtslib/issues/268)).
- EVENTs that share a node id and have different name constraints ("First event", "Second event") get `name/value` predicates in their Web Template AQL paths, like other renamed siblings, so they stay apart through `webTemplateToOpt` ([#269](https://github.com/ErikSundvall/ehrtslib/issues/269)).
- `webTemplateToOpt` rebuilds an ITEM_SINGLE leaf (`…/item[at0005]`) as an ELEMENT with its value, as it does for `items[…]`; it used to put the bare value under `item` and lose the node id ([#270](https://github.com/ErikSundvall/ehrtslib/issues/270)).

## [0.10.0] - 2026-11-01

- **Behaviour change.** Both ADL2 coding systems are supported in one build, with the coding system read from each artefact's root node id: at-coded (ADL 2.4, the default, experimental until AM 2.4.0) and id-coded (ADL 2.0–2.3). New `adl2CodingSystemOf`, `isAdl14Artefact`, `adl2VersionFor` and `AT_CODED_ADL_VERSION`; `hasAdl14NodeIds` is removed (use `isAdl14Artefact`). See docs/ADL_SUPPORT.md "ADL2 coding systems" and ADR 0015 ([#246](https://github.com/ErikSundvall/ehrtslib/issues/246)).
- **Breaking.** Node ids map from id-codes to at-codes by the ADL2 rule everywhere (`id1` → `at0000`, `id5` → `at0004`, `id1.1` → `at0000.1`). Web Template, FLAT and STRUCTURED paths and node ids of id-coded templates used `id5` → `at0005` and so were off by one; they now match the OPT 1.4 and the data a CDR holds. Path matching (`resolveAomPath`, `ArchetypePathResolver`, FLAT/RM navigation) follows the same rule ([#246](https://github.com/ErikSundvall/ehrtslib/issues/246)).
- **Behaviour change.** The Web Template of an ADL2 template up-converted from OPT 1.4 equals the OPT 1.4 one, in both coding systems: ids, names, paths, occurrences and node ids. Node ids minted on up-conversion and node ids of data values are left out of paths; a term missing from the archetype's own terms no longer falls back to another archetype's term with the same code ([#246](https://github.com/ErikSundvall/ehrtslib/issues/246)).
- **Behaviour change.** at-coded ADL2 output is stamped `adl_version=2.4.0` (`upconvertOpt14ToAdl2`, `convertAdl14ToAdl2`, `OPT2Serializer`, OET compile); id-coded output keeps `2.0.5` / `2.0.6`. Parsing an at-coded artefact with an ADL 2.0–2.3 header adds a warning and does not fail ([#246](https://github.com/ErikSundvall/ehrtslib/issues/246)).
- Canonical JSON, XML and YAML deserializers accept generic `_type` names such as `DV_INTERVAL<DV_COUNT>` (resolved to the base class) ([#249](https://github.com/ErikSundvall/ehrtslib/issues/249)).
- FLAT and STRUCTURED read and write nodes whose path has a `name/value` predicate (name-constrained sibling ELEMENTs, CLUSTERs and SECTIONs). They were dropped on write and stored under a broken property on read. A bare FLAT key on a `DV_IDENTIFIER` reads as `|id`, as EHRbase reads it ([#250](https://github.com/ErikSundvall/ehrtslib/issues/250)).
- `TemplateValidator` no longer throws on typed RM instances with a `type` attribute (`DV_IDENTIFIER`, `OBJECT_REF`, …) when `validateIntervals` is on. The validators find the RM type by class for typed instances and by `_type` only for plain JSON; typed classes keep the `type` attribute in `_type` ([#247](https://github.com/ErikSundvall/ehrtslib/issues/247)).
- **Behaviour change.** OPT2 text written by `OPT2Serializer` parses back to the same Web Template as the OPT 1.4, for every OPT 1.4 fixture in both coding systems. The ADL2 parser reads `*` upper bounds as unbounded, keeps string value lists (`{"a", "b"}`) as lists and quotes inside strings, applies archetype term scopes to parsed OPT2, and reads a `/regex/` on its own line. The serializer writes the `language` section for OPT 1.4 input, `description.other_details`, template ids with spaces with `_` in their place (the original is kept in `other_details["template_id"]` and restored on parse), and `/.*/` for an unconstrained string ([#252](https://github.com/ErikSundvall/ehrtslib/issues/252)).
- **Breaking.** Node ids minted on OPT 1.4 up-conversion are `at9000+` / `id9000+`, as in Archie, so they never collide with archetype codes. Template content and binding hashes of templates with minted ids change. `OPT2Serializer` marks minted ids with a `synthetic_node_id` entry in `annotations` (on by default; `syntheticNodeIdAnnotations: false` to turn off), and the parser restores the flag, so they stay out of paths after a re-parse ([#252](https://github.com/ErikSundvall/ehrtslib/issues/252)).
- Optional conversion log in Archie's format: `upconvertOpt14ToAdl2(…, { conversionLog: true })` returns the created codes; a previous log passed back in keeps minted codes stable across re-conversions. Off by default. `parseConversionRunLog`, `serializeConversionRunLog` ([#252](https://github.com/ErikSundvall/ehrtslib/issues/252)).
- **Breaking.** id-coded ADL2 → ADL 1.4 codes: node ids never move. A LOCATABLE node id always maps `idN` → `at(N−1)`; a value code that would get the same at-code shares it (same terms), is written back to its bound external code (for example `[openehr::128]`), or else moves to `at9000+` with a warning. Before, the node moved to `at9000+`, so the OPT 1.4 export and the Web Template paths of such a template differed. Node ids of data values (DV_*, CODE_PHRASE, …) are no longer written in ADL 1.4 archetype text. OPT 1.4 export, `ADL14Serializer` and `componentCodeMaps` change for affected archetypes ([#252](https://github.com/ErikSundvall/ehrtslib/issues/252)).
- **Breaking.** Web Templates of id-coded templates list local value codes as ADL 1.4 codes (`at16` → `at0015`), from the same per-archetype map, so FLAT and STRUCTURED codes match the OPT 1.4 and its CDR. New `adl14CodeFor`, `adl14CodeMapFor`, `adl14CodeMapWarnings`; `prepareContribution` down-converts with the map of each draft's bound template, and standalone `downConvertToAdl14` takes `operationalTemplate`; `bindTemplate` warns about moved or written-back value codes. `ADL14Serializer` writes a colliding bound or post-parse value code back as its external code (`property matches {[openehr::128]}`) and drops its local term and binding ([#252](https://github.com/ErikSundvall/ehrtslib/issues/252)).
- The OPT 1.4 export writes `DV_QUANTITY.property` from ADL2 `property matches {[atN]}` (it was dropped), and maps the local symbol codes of `DV_ORDINAL` / `DV_SCALE` lists to ADL 1.4 codes ([#252](https://github.com/ErikSundvall/ehrtslib/issues/252)).
- **Behaviour change.** FLAT writes a coded `LINK.meaning` as `_link:i|meaning|code`, `|meaning|terminology` and `|meaning|value`, the form of the spec's "RM Attributes prefix" example, instead of `_link:i/_meaning|code` ([#250](https://github.com/ErikSundvall/ehrtslib/issues/250)).
- **Behaviour change.** A FLAT or STRUCTURED field key that sets nothing is an `unknown-key` issue with the `unknownKeys` severity instead of being dropped: DV_ORDINAL-style `|code`/`|value`/`|ordinal` on a DV_SCALE node, a bare key on DV_STATE or DV_PARAGRAPH (which have no primitive `value`; it used to build an invalid `value`), and any suffix the type's form does not read. The spec has no FLAT form for DV_SCALE, DV_STATE or DV_PARAGRAPH; `_value`, `_symbol|…`, `_is_terminal` and `_items:i` work ([#250](https://github.com/ErikSundvall/ehrtslib/issues/250)).
- `TemplateValidator` matches same-id siblings by their name constraint, so a second `at0003` with another name (`Organisationsnummer`) is no longer checked against the first sibling's name ([#250](https://github.com/ErikSundvall/ehrtslib/issues/250)).
- The RM instance generator makes instances the canonical JSON deserializer accepts in strict mode, for every fixture: valid `DV_MULTIMEDIA`, `DV_PARSABLE`, `DV_ORDINAL` and `DV_SCALE`, typed primitives, values from C_STRING lists, and no attributes the RM does not have ([#253](https://github.com/ErikSundvall/ehrtslib/issues/253)).

## [0.9.0] - 2026-11-01

- **Behaviour change.** FLAT and STRUCTURED read and write any RM attribute without its own path as `_<attr>` (spec "RM Attributes prefix"), driven by the BMM: `_link:i`, `_feeder_audit/…`, `_other_participation:i`, `context/_participation:i`, `_work_flow_id`, `_guideline_id`, `_instruction_details`, `_uid` at any LOCATABLE, `_normal_range` / `_other_reference_ranges:i`, `_mapping:i`, `_hyperlink`, and so on, with the spec's FLAT forms for LINK, PARTICIPATION, FEEDER_AUDIT, OBJECT_REF, DV_INTERVAL and the other RM Mappings types. RM → FLAT now writes every set attribute that has no other path, so RM → FLAT → RM no longer loses participations, feeder audits, links, workflow ids or `DV_INTERVAL` values. DV_INTERVAL writes `|…_unbounded` only when true and `|…_included` only when false, as the spec says. A free-text value on a coded node is written as `|other`. `EVENT.offset` is computed and not written. `ACTIVITY.action_archetype_id` defaults to the template's pattern (`/pattern/`), else `/.*/`. Attributes that are not RM attributes of the object, or that the template already covers, are `unknown-key` issues with the `unknownKeys` severity. The deprecated `collectExpectedFlatKeys` is removed (use `validateFlatPayload`). See docs/SIMPLIFIED_FORMATS.md "RM attributes (`_` prefix)".
- **Breaking.** FLAT and STRUCTURED serializers write the **output flavour** by default: every value at its own path and no `ctx/` keys, as Better and EHRbase return it. Pass `flavor: "input"` for the previous style with `ctx/` keys. RM-mandatory attributes that the template does not constrain now round-trip: Web Templates have `inContext` nodes for composition `category`, `context/start_time`, `context/setting`, `composer`, `language`, `territory`, entry `language`, `encoding`, `subject`, event `time`, `history_origin`, action `time` and `ism_transition`, instruction `narrative`, and activity `timing` / `action_archetype_id` ([#239](https://github.com/ErikSundvall/ehrtslib/issues/239)).
- **Breaking.** FLAT paths follow the spec's level removal: no `data` segment for HISTORY, and no event segment for a single EVENT with max 1 (`…/blood_pressure/data/any_event:0/systolic` becomes `…/blood_pressure/any_event:0/systolic`, or `…/blood_pressure/systolic` when the event is not repeatable). Archetyped `other_context` content has paths under `context/`. The old form is not read: it is not a spec path, and no other platform writes it ([#239](https://github.com/ErikSundvall/ehrtslib/issues/239)).
- **Behaviour change.** FLAT and STRUCTURED → RM accept both flavours and fill values in the order explicit path → `ctx/` → default (`ctx/` no longer overwrites a path).
