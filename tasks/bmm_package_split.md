# Model megaclass split into BMM packages

The five model monoliths (`openehr_base.ts`, `openehr_lang.ts`, `openehr_term.ts`,
`openehr_rm.ts`, `openehr_am.ts`) are now one module per BMM package, generated by
[`tasks/split_model_by_bmm_packages.ts`](split_model_by_bmm_packages.ts) from
[`tasks/bmm_package_map.json`](bmm_package_map.json).

```
deno run -A tasks/split_model_by_bmm_packages.ts             # all components, dependency order
deno run -A tasks/split_model_by_bmm_packages.ts rm --dry-run
deno run -A tasks/verify_bmm_split_api.ts                    # public API is unchanged
```

Pre-split copies live in `tasks/_monolith_backup/` (self-ignored) so the splitter stays
re-runnable; pass `--refresh-backup` after hand-editing a package file if you ever need to
re-derive the backup from the current tree.

## Path rules

No package names are invented. A BMM package `org.openehr.<comp>.s1[.s2...sn]` maps to:

| BMM package | file |
|---|---|
| `org.openehr.rm.composition` | `rm/composition/composition.ts` |
| `org.openehr.rm.composition.content` | `rm/composition/content.ts` |
| `org.openehr.rm.composition.content.entry` | `rm/composition/content/entry.ts` |

Each top-level package is a directory with a `mod.ts` barrel; the component `mod.ts`
re-exports every package barrel, and `<comp>/openehr_<comp>.ts` plus the root
`openehr_<comp>.ts` are re-export shims, so every existing import path still resolves.

## Buckets that are not BMM packages

- `<comp>/_shared.ts` — file-level internals the monolith kept private (`type T = any`,
  `TYPE_REGISTRY`, `Operation`, `accuracyAsNumber`, the BMM `= any` placeholders in `lang`)
  plus the `TYPE_REGISTRY` helpers `registerType` / `isTypeRegistered` / `getRegisteredTypes`.
  Not re-exported wholesale; the three helpers are re-exported by name from `base/mod.ts`
  because they were public before.
- `<comp>/_unassigned.ts` — exported symbols with no entry in the package map. The splitter
  warns about each one. They stay in the public barrel.

| component | unassigned symbols |
|---|---|
| `base` | `Byte` |
| `lang` | `BMM_PROCEDURE_TYPE`, `BMM_FUNCTION_TYPE`, `BMM_TUPLE_TYPE`, `BMM_SIMPLE_CLASS`, `BMM_GENERIC_CLASS` |
| `rm` | `DvTextInit`, `DvCodedTextInit`, `CodePhraseInit`, `CompositionInit` (constructor init option types) |
| `am` | 21 AOM 1.4 / abstract AOM2 classes: `C_PRIMITIVE`, `EXPR_ITEM`, `EXPR_LEAF`, `EXPR_OPERATOR`, `EXPR_UNARY_OPERATOR`, `EXPR_BINARY_OPERATOR`, `C_DOMAIN_TYPE`, `C_ORDINAL`, `C_CODED_TEXT`, `C_QUANTITY`, `C_QUANTITY_ITEM`, `ORDINAL`, `ASSERTION`, `ASSERTION_VARIABLE`, `OPERATOR_KIND`, `CARDINALITY`, `ARCHETYPE_INTERNAL_REF`, `C_SINGLE_ATTRIBUTE`, `CONSTRAINT_REF`, `C_MULTIPLE_ATTRIBUTE`, `ARCHETYPE_ONTOLOGY` |

`org.openehr.base.base_types.builtins` and `org.openehr.base.foundation_types.functional`
have no implementation in the enhanced model, so no file is emitted for them.

## Two cycle problems the split had to solve

**Mutually importing packages.** `Ordered extends Any` puts `foundation_types.primitive_types`
downstream of `foundation_types`, while `Any.equal()` returns a `new Boolean(...)`, putting it
back upstream. ESM only tolerates that if the module needing a binding while its own body runs
is entered first, so every barrel opens with side-effect imports that fix the entry order for
such groups. Only `base` has one:
`primitive_types.ts -> foundation_types.ts -> structure.ts`.

**Bridge classes.** `ARCHETYPE_SLOT` (mapped to `aom2.constraint_model`) extends
`C_REFERENCE_OBJECT`, which the map does not place, which in turn extends `C_OBJECT`
(also `aom2.constraint_model`). Left in `_unassigned.ts` that chain needs each module's classes
at the other's definition time, which no evaluation order can satisfy. An unmapped class that a
mapped class extends is therefore placed in the package of its nearest mapped ancestor — still a
package name from the map. `C_REFERENCE_OBJECT` is the only case in the whole model.

## Verification

- `deno check` clean for all five barrels, and `deno task check` passes repo-wide.
- `deno run -A tasks/verify_bmm_split_api.ts`: exported symbol sets are byte-identical before
  and after for all five components, via both `<comp>/mod.ts` and `openehr_<comp>.ts`
  (base 65, lang 151, term 6, rm 150, am 97 — nothing missing, nothing added).
- `deno test --allow-read --no-check test_data/tests/`: 596 passed / 67 failed, an identical
  pass/fail set to the same tree with the monoliths restored, so the split causes no
  regressions. Those 67 are pre-existing: a missing `test_data/test_data` fixture symlink,
  YAML tests needing `--allow-env`, `DOMParser` not implemented in Deno for terminology XML,
  RM instance-generator slot-coverage benchmarks, and `xml_serializer.test.ts` importing
  `TERMINOLOGY_ID` (a `base` class) from `rm/openehr_rm.ts`.
